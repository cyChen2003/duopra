概览

边听，边说，边做。

全双工模型已经知道什么时候听、什么时候说。Duopra 还知道什么时候动手——它在话说到一半时自己调用工具，这些动作从不出声。

听说一格一秒

边听边说

每一秒，Duopra 都在决定这一秒是听还是说。你说完它接话，你句中停顿它不抢，你插话它就让。

说着话就动手

工具调用走一条私有通道，在 Duopra 还在说话时就发出。调用本身从不被念出来，念出来的只有结果。

amount: 100 150 其实是 150 欧元，不是 100。

跟得上改口

请求说到一半改了数值，进入工具的只有最后那个值——被放弃的 100 不会。

modify_autopay(mortgage → savings)modify_autopay(credit_card → checking)

一句话里的多步任务

一口气说出的两项修改，变成两次调用；每一项都等结果返回之后才念出。

flight.status(flight: "CA1701")一个工具
query(task: "帮我改签到周五")你的后台 agent

后台模型，像工具一样调用

接上一个后台模型，它就成了又一个工具 query(task)。Duopra 把事情交给后台，和调用任何工具一样：对话不停，也听不到任何交接。

{ "name": "home.lights",
  "description": "开关某个房间的灯",
  "parameters": {
    "room": "string",
    "on": "boolean" } }你的工具

工具由你来定

一个工具就是一份 JSON schema：名字、描述和参数，在运行时提供。写下你自己的工具——日程、数据库、家里的设备——Duopra 就能调用它。

真实录音

逐秒看它是怎么发生的。

两段评测中的会话，按录音时间重放。

关于录音
这是挑选出来的两段会话，不代表成功率。转写、工具调用和发生的先后来自保存的运行记录；波形由音频测得。
关于音频
用户音频来自 Full-Duplex-Bench v3。助手音频是同一次运行录下的输出，用的是原 projector，不是最终版。
工具与转写
工具都是基准里的模拟接口，不涉及任何真实金融服务。助手转写来自 ASR，可能有识别错误。
工作方式

说什么、做什么，由同一个策略决定。

每一秒，Duopra 读入新的音频和已返回的工具结果，同时输出三样东西。

yt = ( mt , wt , at )
话轮状态听还是说
文字由 talker 念出
动作从不出声

这是一个因果策略，条件是到目前为止的音频、已注入的观测和它自己之前的输出。对话与工具调用一起决定，不在组件之间来回传递。

后台也只是一个工具。

后台 agent 以 query(task) 的形式出现，参数是对用户任务的完整描述。直接调用还是委派，是同一个策略做出的同一类决定——没有外部调度器。

结果落在单元边界上。

运行时异步执行每次调用，并在结果返回后的第一个 1 秒边界注入上下文。等待期间模型照常听、照常说，结果到了才报出数值。

分三个阶段训练

每个阶段解决一个问题：动作的格式、要不要动手，以及 thinker 一变就会跑偏的声音。

  1. 1Stage 1

    协议 SFT

    学会动作的格式。

    在合成会话上对 thinker 做监督微调，示范完整的协议：按 schema 调用工具，结果返回前不播报，只追问缺失的值。

    Duopra-SFT · Pass@126.0%调用格式正确，但仍有 55% 的会话一次也没调用。
  2. 2Stage 2

    全双工强化学习

    学会何时动手。

    在 thinker 的 LoRA 上做 Dr. GRPO，每个任务 8 个 rollout；沙盒给每个 rollout 播放同一个脚本化用户。时间锚定的截止与结果分级，奖励及时、完整、有依据的调用。

    Duopra · Pass@126.0→47.7%没有调用的会话从 55% 降到 19%。
  3. 3Stage 3

    只修 projector

    让声音保持清晰。

    后训练会改变 thinker 的隐藏状态，而这些状态决定 talker 怎么发音。只在缓存特征上重训两者之间的 projector；文字、控制 token 和调用都不受影响。

    试点 · 中文字错误率5.17→1.78%88 条试点样本；后训练前为 2.05%。

论文

Duopra: From Full-Duplex Conversation to Full-Duplex Agency

代码与模型权重现已公开，预印本即将公开。

阅读摘要

全双工交互模型已经展现出很强的对话智能，能够自然、低延迟地完成话轮转换、附和与打断。然而，要成功完成任务，还需要任务能力（task agency）——及时调用工具，并在用户改口后修正参数。在前后台架构中，委派错误与执行错误往往纠缠在一起，掩盖了主要瓶颈。我们首先在 Full-Duplex-Bench（FDB）v3 上研究这一问题：Realtime-Venus-Audio 搭配其原始 Harness 只在 11.0% 的会话中委派，通过率为 4.7%；即使后台完美，最多也只能提升 6.3 个百分点。随后我们提出 Duopra，它直接执行不出声的工具调用，并把委派后台视为一次工具选择。三阶段训练结合了监督微调、带时间锚定截止与分级奖励的全双工强化学习，以及只训练 projector 的 talker 修复。后台固定时，Duopra 把通过率从 4.7% 提高到 44.7%，而换用大得多的后台只带来 4.7 个百分点的提升。它独立运行时达到 47.7%，接开放后台时达到 49.3%，超过所有参与比较的开源系统。补充评测显示，相比基座模型，它的话轮控制与重叠处理更好，但附和有所减少，说明任务能力可以建立在对话能力之上。
