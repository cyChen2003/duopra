Overview

Listen. Speak. Act.

Full-duplex models already know when to listen and when to speak. Duopra also knows when to act — it calls tools itself, mid-sentence, through actions that are never voiced.

listenspeakone cell, one second

Listens while it speaks

Every second, Duopra decides whether to listen or to speak. It takes the turn when you finish, holds back in a mid-sentence pause and gives way when you cut in.

Acts mid-sentence, silently

Tool calls go out on a private channel while Duopra is still talking. The call itself is never spoken — only its result is.

amount: 100 150 It's actually 150 euros, not 100.

Keeps up with corrections

Change a value halfway through a request and only the final value reaches the tool. The abandoned 100 never does.

modify_autopay(mortgage → savings)modify_autopay(credit_card → checking)

Several steps in one request

Two changes asked for in one hesitant breath become two calls, and each is reported only after its result comes back.

flight.status(flight: "CA1701")a tool
query(task: "Rebook me for Friday")your backend agent

Calls a backend like any tool

Connect a backend model and it becomes one more tool, query(task). Duopra hands work over the way it calls any tool: mid-conversation, with no pause and no hand-off you can hear.

{ "name": "home.lights",
  "description": "Lights on or off",
  "parameters": {
    "room": "string",
    "on": "boolean" } }your tool

Bring your own tools

A tool is a JSON schema: a name, a description and its parameters, supplied at run time. Write your own — your calendar, your database, your home — and Duopra can call it.

How it works

One policy decides what to say and what to do.

Every second, Duopra reads the new audio and any tool results, then emits three things at once.

yt = ( mt , wt , at )
Turn statelisten or speak
Wordsvoiced by the talker
Actionnever voiced

One causal policy, conditioned on the audio so far, the observations injected so far and its own past outputs. Conversation and tool use are decided together, not handed between components.

The backend is one more tool.

A background agent is exposed as query(task), whose argument is a self-contained description of the user's task. Calling a tool directly or delegating is the same kind of decision, made by the same policy — there is no external dispatcher.

Results land on unit boundaries.

A runtime executes each call asynchronously and injects the result at the first one-second boundary after it returns. The model keeps listening and speaking while it waits, and reports a value only once it has arrived.

Trained in three stages

One stage for each problem: the form of an action, the decision to act, and a voice that drifts when the thinker changes.

  1. 1Stage 1

    Protocol SFT

    Teaches the form of an action.

    Supervised fine-tuning of the thinker on synthetic sessions that demonstrate the protocol: call tools by schema, wait for the result before reporting it, ask only for missing values.

    Duopra-SFT · Pass@126.0%Calls are well formed, but 55% of sessions still end without one.
  2. 2Stage 2

    Full-duplex RL

    Teaches the decision to act.

    Dr. GRPO on a thinker LoRA, eight rollouts per task, in a sandbox that plays the same scripted user to every rollout. Time-anchored deadlines and outcome tiers reward calls that are timely, complete and grounded.

    Duopra · Pass@126.0→47.7%Sessions without a call fall from 55% to 19%.
  3. 3Stage 3

    Projector-only repair

    Keeps the voice intelligible.

    Post-training shifts the thinker's hidden states, which condition the talker. Only the projector between them is retrained, on cached features; the text, control tokens and calls are untouched.

    Same thinker · Chinese character error rate6.01→2.58%Base vs. Stage-3 projector, 221-utterance selection set; English WER 9.74→7.66%.

Paper

Duopra: From Full-Duplex Conversation to Full-Duplex Agency

The preprint, the code and the weights are available now.

Read the abstract

Full-duplex interaction models exhibit strong conversational agency, enabling natural, low-latency turn-taking, backchannels, and interruptions. However, completing tasks further requires task agency: timely tool invocation and argument revision following user corrections. Frontend–backend agents separate initiation from execution: the frontend decides whether and what to request, while the backend determines how. Execution can be offloaded, but unsent requests cannot be executed, and incomplete ones can misdirect the backend. On Full-Duplex-Bench v3 (FDB v3), most failures of Realtime-Venus-Audio + Harness in our streaming pipeline occur before a domain tool executes. We introduce Duopra, a full-duplex interaction model that learns task execution alongside conversational control. Duopra treats the backend as a tool, accepting a self-contained natural-language request. Direct calls and backend delegation share an action interface and requirements for faithful initiation and correct execution. Its three-stage training combines protocol SFT, full-duplex RL rewarding timely and complete execution, and projector-only repair of talker conditioning after thinker updates. With the same backend, Pass@1 rises from 4.7% to 44.7%; Duopra achieves 47.7% calling tools directly (26.0% after SFT) and 49.3% with a DeepSeek backend. It improves three FDB v1.0 takeover rates over the base model. These results show that task agency can coexist with key conversational agency.
